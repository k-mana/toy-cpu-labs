CPU の設定

結果をレジスタに書き戻す前に、後続命令の EX へ直接渡す回路です。

分岐 (BEQ など) は EX で結果が決まります。予測が外れると、後ろの2命令を取り消します。

学習ガイド

パイプラインとは

1命令を IF・ID・EX・MEM・WB の5工程に分け、工程ごとに別の命令を同時に処理します。洗濯で「洗う・乾かす・たたむ」を重ねるのと同じ発想です。理想では毎サイクル1命令が完了し、CPI（1命令あたりのサイクル数）は 1 に近づきます。

データハザード（RAW）

前の命令の結果を次の命令がすぐ読むと、まだレジスタに書かれていない値を読んでしまいます。フォワーディングがない CPU は、値が WB で書かれるまで ID で待ちます（ストール）。

フォワーディング

EX/MEM や MEM/WB のパイプラインレジスタにある計算結果を、EX の入力へ直接回します。ALU 命令どうしならストールはゼロになります。

ロード・ユース・ハザード

LW の値は MEM の終わりにやっと手に入るので、直後の命令はフォワーディングがあっても1サイクル待つ必要があります。命令の順番を入れ替えると隠せます。

制御ハザード（分岐）

BEQ の行き先が EX で決まるまで、次に何をフェッチすべきか分かりません。「不成立予測」なら外れたときだけ2命令を取り消し、「停止して待つ」なら毎回2サイクル空きます。

キー操作: → 進む　← 戻る　Space 再生／停止
