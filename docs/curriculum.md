# 学習カリキュラム

この文書は、TOY の各ラボを使ってコンピュータアーキテクチャを順に学ぶための道筋です。独習でも、授業 (90 分 × 6 回程度) でも使えるように、単元ごとに目標・使うラボ・進め方・確認問題を並べています。

## 全体の地図

```
 単元1 命令セットと機械語 ──▶ 単元2 パイプライン ──▶ 単元3 性能の測り方
                                     │
                                     ├──▶ 単元4 キャッシュ ──▶ 単元5 記憶階層とレイテンシ
                                     │
                                     └──▶ 単元6 マルチコアと同期
```

単元1〜3 は順番に進めてください。単元4 以降はどれからでも始められます。

| 単元 | 主なラボ | 主な用語 |
|---|---|---|
| 1 命令セットと機械語 | [命令セット・ラボ](../labs/playground/) | レジスタ、ロード/ストア、即値、分岐、機械語、疑似命令 |
| 2 パイプライン | [パイプライン・ラボ](../labs/pipeline/) | 5 段パイプライン、データハザード、フォワーディング、ロード・ユース、制御ハザード |
| 3 性能の測り方 | [スループット・ラボ](../labs/throughput/) | CPI、IPC、MIPS、レイテンシとスループット、分岐予測、スーパースカラ |
| 4 キャッシュ | [キャッシュ・ラボ](../labs/cache/) | タグ・インデックス・オフセット、連想度、置換方式、書き込み方式、3C |
| 5 記憶階層とレイテンシ | [レイテンシ・ラボ](../labs/latency/) | 局所性、ワーキングセット、ILP、分岐予測ミス、メモリレベル並列性 |
| 6 マルチコアと同期 | [アトミック・ラボ](../labs/atomic/) | 競合状態、不可分性、CAS、スピンロック、LL/SC |

**前提知識**: 2 進数と 16 進数、2 の補数による負の数、簡単なプログラム (変数・ループ・配列) が読めること。

## 単元1 命令セットと機械語

**目標**
- C の小さなループを、ロード/ストア型の命令列に書き直せる。
- 命令が 32 ビットの機械語にどう詰め込まれるかを説明できる。
- 疑似命令と本物の命令の違いを説明できる。

**進め方**
1. [命令セット仕様](isa.md) の §2〜§4.1 を読む。
2. [命令セット・ラボ](../labs/playground/) で「1〜10 の合計」を 1 命令ずつ実行し、レジスタの変化を追う。
3. 「機械語」の表で、`LI` が 1 命令になる場合と 2 命令になる場合を見比べる。
4. [命令セット一覧](../reference/) の「機械語を読む」に、命令セット・ラボに出た機械語を入れて元に戻ることを確かめる。

**確認問題**
1. `ADD r1, r2, r3` の機械語は `0x01123000` です。`SUB r4, r5, r6` の機械語は?
2. `LI r1, 70000` は何命令に置き換わりますか。それはなぜですか。
3. 配列 `int a[8]` の合計を求めるプログラムを書いてください (配列は `.data` に置く)。
4. `BEQ` の飛び先が「PC+1 からの相対」で符号化されているのはなぜでしょう。絶対番地にすると何が困りますか。

<details><summary>答えの例</summary>

1. `0x02456000` (SUB のオペコードは 0x02)
2. 2 命令 (`LUI r1, 1` と `ORI r1, r1, 4464`)。70000 は 16 ビットの符号付き即値 (−32768〜32767) に収まらないため。
3. 命令セット・ラボの例「配列の最大値」を参考に、`BGE` と `MOV` の代わりに `ADD` で足していく。
4. 相対なら 16 ビットで近くの分岐先を表せ、プログラムをどこに置いても機械語が変わらない。絶対番地では大きなプログラムで足りなくなる。
</details>

## 単元2 パイプライン

**目標**
- 5 つの段の役割と、理想状態で CPI が 1 に近づく理由を説明できる。
- データハザード・制御ハザードがいつ起き、何サイクル失うかを予想できる。
- フォワーディングで消えるストールと、消えないストールを区別できる。

**進め方** — [パイプライン・ラボ](../labs/pipeline/)
1. 「理想の流れ」: N 命令が N+4 サイクルで終わる理由を、タイミング図の階段で確かめる。
2. 「データハザード」: フォワーディングを「あり」「なし」で切り替え、ストールの数と CPI を記録する。
3. 「ロード・ユース」: フォワーディングがあっても残る 1 サイクルの待ちを見つけ、命令を並べ替えて消す。
4. 「分岐ループ」: 「不成立予測」と「停止して待つ」で総サイクルを比べ、取り消された命令をタイミング図で数える。

**確認問題**
1. 依存のない 20 命令は何サイクルで終わりますか。パイプラインがなければ?
2. フォワーディングがない CPU で、`ADDI r1, r0, 1` の直後に `ADD r2, r1, r1` を置くと、何サイクルのストールが起きますか。
3. ループの最後の後ろ向き分岐は、ほとんど毎回成立します。「不成立予測」はこの分岐に向いていますか。
4. 「ロード・ユース」の例で、ストールを 0 にする並べ方を見つけてください。

<details><summary>答えの例</summary>

1. 24 サイクル。パイプラインなしなら 100 サイクル。
2. 2 サイクル (ADDI の WB と同じサイクルに ID を終えられるまで待つ)。
3. 向いていない。毎回外れて 2 サイクルずつ失う (単元3 の 2 ビット予測がこれを解決する)。
4. `LW r1` と `LW r3` を先に並べ、その後に `ADD`・`SUB` を置く (結果のレジスタ値が変わらないことも確かめる)。
</details>

## 単元3 性能の測り方

**目標**
- 実行時間 = 命令数 × CPI ÷ クロック周波数 を使って構成を比べられる。
- レイテンシとスループットの違いを説明できる。
- ハザードの種類ごとに、効く対策 (フォワーディング・分岐予測・並べ替え・発行幅) を選べる。

**進め方** — [スループット・ラボ](../labs/throughput/)
1. 4 つのプログラムを既定の構成で実行し、「サイクルの内訳」で損失の原因を読む。
2. 構成を 1 つずつ変えて「比較表に記録」し、何が効いたかを表にまとめる。
3. 4 つの課題をすべて達成する。課題3 (命令の並べ替え) は単元2 の 4 の発展です。

**確認問題**
1. CPI 1.5・1 GHz の CPU と、CPI 1.0・800 MHz の CPU では、同じプログラムでどちらが速いですか。
2. 「依存チェーン」を 2 命令幅にしても速くならないのはなぜですか。
3. 平均レイテンシは 5.4 サイクルなのに、IPC が 0.8 になるのはなぜですか。

<details><summary>答えの例</summary>

1. 1 命令あたり 1.5 ns と 1.25 ns なので、後者が速い。
2. すべての命令が直前の結果を使うので、同じサイクルに並べて実行できる命令がない。
3. パイプラインでは複数の命令が重なって進むので、1 命令の所要時間 (レイテンシ) が長くても、毎サイクル命令が完了しうる (スループット)。
</details>

## 単元4 キャッシュ

**目標**
- 番地をタグ・インデックス・オフセットに分け、どのセットに入るかを計算できる。
- 3 種類のミス (初期参照・容量・競合) を見分け、それぞれに効く対策を挙げられる。
- ライトバックとライトスルーの違いを、メモリの中身の食い違いで説明できる。

**進め方** — [キャッシュ・ラボ](../labs/cache/)
1. 「配列の合計」でライン長を 4・16・32 バイトに変え、ヒット率の変化を記録する (空間的局所性)。
2. 「2配列の加算」で連想度を 1・2・4 と上げ、競合ミスが消えるところを探す。
3. 「行列の列方向走査」と「ストライドアクセス」で容量ミスを観察する。
4. 書き込み方式を切り替え、メインメモリの表示でダーティなライン (未書き戻し) を見つける。

**確認問題**
1. 128 B・16 B ライン・ダイレクトマップのキャッシュで、番地 0x1A4 はどのセットに入り、タグはいくつですか。
2. 競合ミスを減らす方法を 2 つ挙げてください。
3. ライトバックでは、メモリの値が古いままになることがあります。それが問題になるのはどんなときですか。

<details><summary>答えの例</summary>

1. ライン番号 = 0x1A4 ÷ 16 = 26、セット = 26 mod 8 = 2、タグ = 26 ÷ 8 = 3。
2. 連想度を上げる。データの配置 (番地) をずらして同じセットに集まらないようにする。
3. 他の装置 (別のコアの持つキャッシュ、DMA など) がメモリを直接読むとき。単元6 のキャッシュ一貫性につながる。
</details>

## 単元5 記憶階層とレイテンシ

**目標**
- ワーキングセットの大きさと、各階層の容量・レイテンシから性能を見積もれる。
- 依存チェーンが命令レベル並列性 (ILP) を制限することを説明できる。
- 予測しにくい分岐のコストと、分岐をなくす書き方を説明できる。
- ミスを重ねる (メモリレベル並列性) ことでスループットを上げる考え方を説明できる。

**進め方** — [レイテンシ・ラボ](../labs/latency/) のレッスン 1〜5 を順に。各レッスンの「試してみよう」を全部行い、比較欄の数字を記録する。

**確認問題**
1. レッスン2 で、2 KB と 16 KB の差が約 2 倍、16 KB と 64 KB の差が約 3 倍になります。この倍率を、L1・L2・L3 のレイテンシから説明してください。
2. 「MUL 4本の鎖」が「1本の鎖」の約半分のサイクルで終わるのはなぜですか。4 分の 1 にならないのはなぜですか。
3. 連結リストをたどる処理を速くするには、データ構造をどう変えればよいでしょう。

<details><summary>答えの例</summary>

1. ループ 1 周の時間は、ロードの待ちとループの命令・分岐予測ミスの和です。ロードの待ちが L1 (4) → L2 (12) → L3 (40) と増えるので、ロード以外の固定分を含めた比が 2〜3 倍になる。
2. 4 本の鎖は互いに独立なので、MUL の 3 サイクルの待ちが重なる。ただしループの `SUBI`・`BNEZ` の時間と、1 サイクルに 1 命令しか発行できない制約が残る。
3. ノードを配列に並べる、次に読むノードを先に読んでおく (ソフトウェアプリフェッチ)、複数のリストを同時にたどる、など。
</details>

## 単元6 マルチコアと同期

**目標**
- 更新消失が起きる命令の並びを示せる。
- 不可分な命令 (AMOADD・CAS・XCHG・SC) がなぜ必要かを説明できる。
- CAS ループ・スピンロック・LL/SC の違いを説明できる。

**進め方** — [アトミック・ラボ](../labs/atomic/) のレッスン 1〜5 を順に。各レッスンで、まず手で (コアのボタンで) 危ない順番を作り、次に「1000回ランダムに実行」で頻度を確かめる。

**確認問題**
1. `counter++` を 2 コアで 3 回ずつ行うとき、最終値の最小はいくつですか。そうなる順番を書いてください。
2. INCM は 1 命令なのに、なぜ不可分ではないのですか。
3. スピンロックの「読んでから書く」版を、AMOADD だけで正しく直せますか。

<details><summary>答えの例</summary>

1. 2。例: コア0 が 0 を読む → コア1 が2周して counter = 2 → コア0 が 1 を書く → コア1 が 3 周目で 1 を読む → コア0 が残り2周して counter = 3 → コア1 が 2 を書く。コアのボタンでこの順に進めると再現できる。
2. CPU の内部で「読み出し」「書き込み」の 2 つの μop に分かれ、その間に他のコアが割り込めるから。
3. 「チケットロック」の形にすれば直せる (AMOADD で整理券を取り、自分の番号が呼ばれるまで待つ)。
</details>

## 次の一歩

カリキュラムを終えたら、[拡張ガイド](extending.md) を読んで、自分で命令やラボを作ってみてください。たとえば次のようなものは、今の枠組みのまま作れます。

- キャッシュ一貫性 (MSI プロトコル) を観察するラボ
- アウトオブオーダー実行 (スコアボード・Tomasulo) のタイミングモデル
- 仮想記憶 (TLB とページテーブル) を加えたメモリのポート
