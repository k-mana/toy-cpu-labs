# タイミングモデル

版: 1.0 — 実装: `core/pipeline.js`, `core/inorder.js`, `core/cache.js`, `core/hierarchy.js`, `core/predictor.js`

タイミングモデルは、Machine の実行記録 (完了した命令の列) を受け取って「その命令がいつ何をしたか」を計算します。命令の結果 (レジスタやメモリの値) には影響しません。

すべてのモデルは同じ使い方です。

```js
const model = new PipelineModel(config);   // または InOrderModel
for (const rec of trace) model.push(rec);  // 1命令ずつ。push は その命令のタイミングを返す
const summary = model.finish();            // 総サイクルなど
```

サイクルは **0 から数えます**。ラボでは 1 から表示することがあります。

## 1. 5段パイプライン (`PipelineModel`)

IF (取り込み)・ID (解読とレジスタ読み出し)・EX (実行)・MEM (メモリ)・WB (書き戻し) の 5 段で、命令を順番どおり (in-order) に流すモデルです。パイプライン・ラボとスループット・ラボが使います。

### 1.1 設定

| 項目 | 既定値 | 意味 |
|---|---|---|
| `pipelined` | `true` | `false` なら 1 命令ずつ 5 サイクルかけて実行する |
| `width` | 1 | 1 サイクルに取り込める命令数 (スーパースカラの幅) |
| `forwarding` | `true` | EX/MEM・MEM/WB から EX への転送路があるか |
| `branch` | `'not-taken'` | 分岐の扱い (§4) |
| `units` | alu 1・mul 1・div 1 | 分類ごとの EX のサイクル数と、パイプライン化されているか |
| `memTime(rec)` | 常に 1 | MEM のサイクル数。キャッシュミスを表すのに使う |
| `serializeMemory` | `true` | メモリポートは 1 つ (MEM を使う命令は同時に 1 つ) |
| `program` | なし | 渡すと、予測が外れたときに誤って取り込んだ命令も記録する |

### 1.2 規則

命令 i がステージ s に入るサイクルを t[s]、そのステージで働くサイクル数を d[s] とします (d = [1, 1, EX 時間, MEM 時間, 1])。P を直前の命令、Q を `width` 個前の命令とします。

```
IF  = max(P.IF, Q.ID, 取り込み再開サイクル)            非パイプラインなら max(…, P.WB + 1)
ID  = max(IF + 1,           P.ID,  Q.EX)
EX  = max(ID + 1,           P.EX,  Q.MEM, 演算器が空く時刻, 値がそろう時刻)
MEM = max(EX + d[EX],       P.MEM, Q.WB,  メモリポートが空く時刻)
WB  = max(MEM + d[MEM],     P.WB,  Q.WB + 1)
```

- 各段には同時に `width` 個までしか入れず、命令は前の命令を追い越しません。
- **値がそろう時刻** (生産者の結果を後続が EX で使える最初のサイクル):

  | | ALU・乗除算・ジャンプ | ロード・メモリ読み書き |
  |---|---|---|
  | フォワーディングあり | 生産者の EX + d[EX] | 生産者の MEM + d[MEM] |
  | フォワーディングなし | 生産者の WB + 1 | 生産者の WB + 1 |

  レジスタファイルは前半で書き、後半で読みます。そのため、フォワーディングなしでは生産者の WB と同じサイクルに ID を終えられます。ストアも、書く値 (rt) を EX でそろえる必要があるものとして扱います。

- **ロード直後の使用**は、フォワーディングがあっても 1 サイクル待ちます。
- パイプライン化されていない演算器は、前の命令の EX が終わるまで次の命令を受け付けません。1 命令幅では EX 段そのものが塞がるので、違いは 2 命令幅で現れます。

### 1.3 分岐とジャンプ

| 命令 | 決まるサイクル | 外れたとき |
|---|---|---|
| 条件分岐 | EX の最後 | 次のサイクルから正しい命令を取り込む (1 命令幅なら 2 サイクルの損失) |
| 直接ジャンプ (`JAL`) | `stall` と `not-taken` では ID の最後。予測器があれば損失なし | 1 サイクルの損失 |
| 間接ジャンプ (`JALR`) | EX の最後 (`perfect` 以外は毎回外れ扱い) | 2 サイクルの損失 |

`stall` 方式では、分岐が決まるまで取り込みを止めます (取り消す命令はありません)。予測方式では、予測した道の命令を取り込み続け、外れたら取り消します。`program` を渡すと、取り消した命令が `squashed` に入ります。

### 1.4 待ちの表示

段 s に `t[s+1] − t[s]` サイクルいて、働くのが `d[s]` サイクルなら、残りは「待ち」です。

- IF・ID の待ちは**前半**に置きます (保持されて待ち、最後のサイクルで先に進む)。
- EX・MEM の待ちは**後半**に置きます (仕事をしてから、次の段が空くのを待つ)。

各命令の `waits` に、待った段と理由 (`data`: 値待ち・`unit`: 演算器待ち・`memport`: メモリポート待ち・`pipeline`: 前の命令が詰まっている) が入ります。`fwd` には、各ソースレジスタの値をどこから受け取ったか (`RF`・`EX/MEM`・`MEM/WB`) が入ります。

### 1.5 集計

`finish()` は次を返します。

| 名前 | 意味 |
|---|---|
| `cycles`, `instructions`, `ipc`, `cpi` | 総サイクル (最後の WB + 1)、命令数、IPC、CPI |
| `ideal` | ハザードがないときのサイクル。パイプラインなら ⌈N / 幅⌉ + 4、なしなら 5N |
| `lost` | `cycles − ideal` |
| `data`, `ctrl`, `other` | 損失の内訳 (データハザード・制御ハザード・その他)。合計は `lost` |
| `mispredicts`, `branches`, `forwards`, `memSlow`, `latency` | 予測ミス、分岐数、転送の回数、MEM が 2 サイクル以上だった命令数、平均レイテンシ |

`data` と `ctrl` の合計が `lost` を超える (待ちが重なっている) ときは、比率を保って `lost` に収まるよう縮めます。

## 2. インオーダー発行モデル (`InOrderModel`)

段を描かずに、命令ごとの「発行」と「結果が出るまで」に集中するモデルです。レイテンシ・ラボが使います。

- 1 サイクルに 1 命令を、順番どおりに発行します。
- 発行は、ソースレジスタの値がそろうまで待ちます。待っている間は後ろの命令もすべて止まります。
- 結果が出るまでのサイクルは分類で決まります (既定: alu 1・mul 3・div 20、ロードはメモリ階層に問い合わせる)。
- `unpipelined` に挙げた分類 (既定: div) は、前の命令が終わるまで次を発行できません。
- ストアは待たせません (書き込みバッファに入るとみなす)。
- ロードが L1 でミスするとき、処理中のミスが `mshr` 個あれば、どれかが終わるまで発行を待ちます。
- 分岐は分岐予測器 (既定 `bimodal`) で判定し、外れると `mispredictPenalty` サイクル (既定 15) 発行が止まります。間接ジャンプは `perfect` 以外では毎回外れ扱いです。

`push()` は `{ issue, done, stall, cause, level, latency, mispredicted }` を、`finish()` は最後の結果がそろう時刻を総サイクルとして返します。待ちは `mem` (メモリ待ち)・`alu` (演算待ち)・`brm` (予測ミス) に分けて数えます。

## 3. キャッシュ (`Cache`)

| 項目 | 既定値 | 意味 |
|---|---|---|
| `size`, `lineSize` | — , 16 | 容量とライン長 (バイト、2 のべき乗) |
| `ways` | 1 | 連想度。0 ならフルアソシアティブ |
| `policy` | `'LRU'` | `LRU`・`FIFO`・`RANDOM` (乱数はシード付き) |
| `write` | `'back'` | `back` (ライトバック) か `through` (ライトスルー) |
| `writeAllocate` | back なら真、through なら偽 | 書き込みミスでラインを載せるか |
| `hitTime`, `missPenalty` | 1, 20 | ヒットのサイクル、ライン 1 つを運ぶサイクル |
| `backing` | なし | 下位のメモリ。渡すとデータを持つキャッシュになり、ポートとして使える |
| `classify` | 偽 | ミスを 3C に分類する |

- 番地は `ライン番号 = 番地 ÷ ライン長`、`セット = ライン番号 mod セット数`、`タグ = ライン番号 ÷ セット数` に分けます。
- 空きウェイがあれば番号の小さいものから使い、なければ置換方式で選びます。
- アクセスのサイクル: ヒット `hitTime`。ミスでラインを載せると `+ missPenalty`。追い出したラインがダーティなら、さらに `+ missPenalty`。ライトスルーの書き込みは待たせません (書き込みバッファ)。
- **3C 分類**: そのラインに初めて触れたなら「初期参照」。同じ容量のフルアソシアティブ LRU キャッシュなら当たっていたなら「競合」。それでも外れるなら「容量」。

## 4. 分岐予測 (`createPredictor`)

| 種類 | 振る舞い |
|---|---|
| `stall` | 予測しない。分岐のたびに取り込みを止める |
| `not-taken` | 常に不成立と予測 |
| `taken` | 常に成立と予測 (飛び先は分かっているものとする) |
| `bimodal` | 分岐ごと (PC ごと) の 2 ビット飽和カウンタ。初期値 1 (弱い不成立)。2 以上なら成立と予測 |
| `perfect` | 常に当たる (理論上の上限を見るため) |

## 5. メモリ階層 (`MemoryHierarchy`)

タグだけのキャッシュを何段か重ね、その下に DRAM を置いたモデルです。

- ロードは上の段から探し、見つかった段のレイテンシがかかります。そのラインは見つかった段より上のすべての段に載せます (包含)。
- 各ラインは「いつ届くか」を覚えています。まだ届いていないラインに当たったら、届くまで待ちます (同じラインへのミスが重なる様子を表すため)。
- `prefetch: n` なら、L1 でミスしたとき、続く n ラインも (L1 になければ) 取りに行きます。
- ストアはラインを L1 まで持ってきますが、待たせません。

## 6. 基準構成

ラボが使っている構成に名前を付けておきます。新しい教材を作るときや、結果を人と比べるときの基準にしてください。

| 名前 | 使うラボ | 命令セット | モデルと主な設定 |
|---|---|---|---|
| **TOY-5** | パイプライン・ラボ・スループット・ラボ | TOY-IM | `PipelineModel`。メモリ 64 B (パイプライン・ラボ) / 1 KiB (スループット・ラボ)。スループット・ラボは MUL 3 サイクル・非パイプライン、ミスは 8 サイクル |
| **CL-1** | キャッシュ・ラボ | TOY-IM | `Machine` + データを持つ `Cache`。メモリ 1 KiB、ミス 20 サイクル、3C 分類あり |
| **LT-1** | レイテンシ・ラボ | TOY-IM | `InOrderModel` + `MemoryHierarchy`。64 B ライン、L1 4 KiB/4・L2 32 KiB/12・L3 128 KiB/40・DRAM 200 (すべてフルアソシアティブ LRU)、MUL 3・DIV 20 (非パイプライン)、予測ミス 15、MSHR 8、メモリ 1 MiB |
| **AL-2** | アトミック・ラボ | TOY-IMA + Xmrmw | `Machine` 2 コア、メモリ 16 B、タイミングなし (1 ステップ = 1 命令または 1 μop) |

## 7. モデルの正しさ

`tests/` のテストは、教科書どおりの小さな例 (依存のない N 命令は N+4 サイクル、ロード直後の使用は 1 サイクル待つ、など) を確かめています。また、シミュレータ本体に移す前の各ラボの計算結果と、ランダムに作った数千のプログラムで 1 サイクル単位まで一致することを確かめてから移しています。
